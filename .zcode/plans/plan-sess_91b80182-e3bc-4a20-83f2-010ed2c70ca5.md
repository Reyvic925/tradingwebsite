## Part 1 — Fix the Vercel build error

**Root cause (verified):** In the installed versions, both `react()` and `tailwindcss()` return `Plugin[]` (arrays). My recent change annotated the list as `const plugins: Plugin[] = [...]`, which requires each element to be a single `Plugin` — hence the two `TS2741: Property 'name' is missing in type 'Plugin<any>[]'` errors at columns 30 and 39 (the `react()` and `tailwindcss()` expressions). The original un-annotated line compiled fine because Vite's `UserConfig.plugins` accepts nested plugin arrays.

**Fix:** In `vite.config.ts`, drop the explicit annotation back to `const plugins = [react(), tailwindcss(), localApiPlugin()];` and verify with `npm run build` locally (this runs the same `tsc -b && vite build` Vercel runs).

## Part 2 — Binance-style deposit flow

Rebuild the Wallet page's Deposit tab as a Binance-like flow, keeping the site's dark/amber terminal aesthetic. No backend changes needed (`/api/user/crypto-addresses` already auto-assigns and returns addresses; `/api/transactions` provides history; withdraw endpoint unchanged).

**Changes to `src/pages/Wallet.tsx`:**

1. **Coin selector (replaces plain `<select>`):** custom dropdown with a search input and coin rows showing ticker, full name, and network label (BTC·Bitcoin·Bitcoin network, ETH·Ethereum·ERC-20, USDT·Tether·ERC-20, USDC, BNB·BEP-20, SOL, XRP, ADA, DOGE, MATIC). Each coin maps to its one auto-assigned network.

2. **Network notice + warning banner:** an amber warning styled like Binance's — "Send only {COIN} to this address on the {network} network. Deposits via other networks may result in loss of funds."

3. **Address card (the core Binance element):**
   - Large **QR code** of the address (adding the `qrcode.react` dependency, React 19–compatible) centered on a white rounded card for scannability
   - Full address in monospace with break-all
   - Prominent **Copy Address** button with checkmark/"Copied" feedback
   - Hints row: minimum deposit note, "credited after network confirmation", address stays the same
   - "Generating deposit address…" state while an address for the selected coin is pending

4. **Deposit history** below the address card: recent deposits with status, amount, coin, and time (from existing transactions data).

5. **Withdraw tab:** keeps current logic (amount, coin, destination address, review note) restyled to match.

6. **Removed:** the disabled "Assigned Wallets" fake submit button, the meaningless deposit-amount input, and the duplicate "Your Deposit Addresses" section at the bottom — all superseded by the new flow. The "Recent Transactions" side panel stays.

**Dependency:** `npm install qrcode.react` (^4.2.0).
