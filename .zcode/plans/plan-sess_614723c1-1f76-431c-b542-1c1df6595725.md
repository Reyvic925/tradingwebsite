# Binance-Standard KYC: User Wizard, Real Document Uploads, Admin Review, Withdrawal Gate

## Current state (from exploration)
- Admin approve/reject already works (`api-handlers/admin-kyc.js` + `src/pages/AdminKyc.tsx`), but nothing feeds it: the real KYC page (`KycSubmit.tsx`) is unrouted and `/api/user/kyc` 404s because `api-handlers/user.js` never dispatches to `user-kyc.js`.
- The only reachable KYC flow (Profile page) collects 3 fields and self-verifies after 1.4s — `PUT /api/profile` lets any user set `kyc_status: 'verified'` (security hole).
- No file upload mechanism exists (documents were pasted external URLs). The API router (`api/index.js`) only parses JSON bodies; local dev runs on an in-memory generic table store (`dev-db.js`), so uploads will use client-compressed images sent as base64 in JSON and stored in a new `kyc_files` table — one code path that works in both dev and Supabase modes.

## A. Database
1. Add `kyc_files` table (`id, user_id, kind, mime, size, data_base64, created_at` + index on user_id) to `schema.sql` and a new migration `20260814-add-kyc-files.sql`. Dev mode needs no changes (generic store auto-creates tables).

## B. Backend
2. **New `api-handlers/kyc-upload.js`** (route `/api/kyc-upload`):
   - `POST` — requireUser; body `{ kind: 'document_front'|'document_back', data_url, filename }`; validate mime (jpeg/png/webp) and decoded size ≤ 5MB; insert into `kyc_files`; return `{ file: { id, kind, mime, size } }`.
   - `GET ?id=` — requireUser; allow if file belongs to requester OR requester is admin (`requireAdmin`); decode base64 and stream binary with correct `Content-Type` (this is how admin views documents).
3. **`api-handlers/user.js`**: dispatch `/api/user/kyc` (GET/POST) → existing `user-kyc.js` handler (fixes the 404). Also gate `POST /api/user/withdraw/crypto`: load profile, reject unless `kyc_status === 'verified'`.
4. **`api-handlers/user-kyc.js`** — Binance-standard validation on POST:
   - `personal_data`: first/last name, dob (18+), nationality, country of residence, gender (optional), address `{ street, city, state, postal_code, country }`, document `{ type: passport|national_id|drivers_license, number, expiry_date (must be future) }`.
   - `documents`: array of `{ kind, file_id }`; every file must exist in `kyc_files` and belong to the user; front required; back required unless passport.
   - Guards: 409 if already verified or a pending submission exists (resubmission allowed after rejection).
   - Side effects: set `profiles.kyc_status = 'pending'`; insert "KYC submitted" notification.
5. **`api-handlers/admin-kyc.js`**: GET attaches user email/full_name (best-effort profile lookup); approve → existing behavior + "Identity verified" notification; reject → also set `profiles.kyc_status = 'rejected'` + "KYC rejected" notification including the admin note.
6. **`api-handlers/profile.js`**: remove `kyc_status` from user-writable PUT fields (closes the self-verify hole). **`api-handlers/auth-profile.js`**: signup default `kyc_status` `'pending'` → `'unverified'` (consistent states: unverified → pending → verified/rejected).

Each file: compress → `POST /api/kyc-upload` → inline thumbnail preview. Review summary + submit → `POST /api/user/kyc`.
