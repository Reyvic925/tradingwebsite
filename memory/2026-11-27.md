## Trading activity price masking fix
- `/api/trader-trades` masked prices whenever `price_review_status` was `pending`/`awaiting_history`. Modelled rows use that status too, so all 63 of Mark Hergott's trades showed "Entry Unavailable" / "Historical price verification pending".
- Fix: exempt `modelled=1` rows from masking (they have deterministic model prices, no dated provider quotes to verify); `TradeLog` now carries `modelled`, and the UI labels these rows "Modelled strategy price" with a model-prices-not-exchange-fills explanation in the detail modal.
- Lesson: when adding a new provenance class, audit every API path that filters by generic review-status fields before assuming stored prices will be visible.

## Interpretation caveat for extreme modelled ratios
- User reviewed Mark Hergott's profile and argued the Sharpe 3.05 / 93.65% win rate / 63 trades / avg loss 2.8x avg win look like textbook backtest overfitting, not a good live trader. Asked for "the best option"; chose the prominent caveat over regenerating history, because any backtest is still not a live track record and the profitable modelled series was the agreed goal.
- Added a "How to read these figures" panel above the ratios in `TraderResearch.tsx`: modelled in-sample output, favourable drift, no fees/slippage/fills, Sharpe >3 and win rate >70% are warning signs, small sample, streaks, and "hypothesis to test out-of-sample".
- Added `breakevenWinRate` to `shared/trader-performance.js` and the analytics payload (~73.39% for Mark vs 93.65% reported, ~20 points of margin). Unit-tested.
- Trading activity subtitle now says "Modelled strategy prices, not exchange-confirmed fills" when any row is modelled.
- Decision rule: keep the disclosure prominent; do not soften it to make the numbers look more credible.
